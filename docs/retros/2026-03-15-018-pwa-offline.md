# Retro: #18 PWA Offline Support — Pass

## Plus (reinforce/repeat)

**Process:**
- TDD with Playwright caught the exact user-reported bugs. Tests failed for the right reason (no SW registered → `navigator.serviceWorker.ready` hangs), passed immediately after adding `vite-plugin-pwa`.
- `vite-plugin-pwa` with `generateSW` was the right tool — minimal config, precaches all build assets including lazy route chunks. Both bugs fixed with one plugin addition.
- Plan was short and focused. Spec → implement → done in one session without over-engineering.

**Structural:**
- Workbox precache manifest automatically includes lazy-loaded route chunks, which was the root cause of bug #1 (offline navigation failure). No manual cache list to maintain.
- `context.setOffline(true)` in Playwright is a clean way to test offline behavior — no need for custom network interception.

## Delta (change next time)

**Process:**
- When adding a new test runner (Playwright) alongside an existing one (Vitest), immediately configure both to stay in their lanes. I didn't add `exclude: ["e2e/**"]` to vitest.config.ts until Vitest blew up trying to run Playwright tests. This was predictable and preventable.
- Stopped and waited after the `dev/check` failure instead of diagnosing and fixing in the same turn. The error was obvious (Vitest picking up Playwright's `test.describe`). Don't pause on clear errors — fix them.

**Documentation:**
- `docs/status.md` is not being kept up to date. It's a convention from CLAUDE.md ("Status — docs/status.md updated every cycle") but we're not following it. Either update it as part of each increment or drop the convention.
- The brainstorming skill writes specs to `docs/superpowers/specs/`. This ties our repo's documentation structure to a specific plugin. Specs should go somewhere plugin-agnostic like `docs/plans/` (which we're already using). Override the default in CLAUDE.md.

**Structural:**
- The app was called "Spacer PWA" from day one (CLAUDE.md title) but had zero PWA infrastructure through two full bootstraps. If the project identity includes "PWA", the first increment should include minimum PWA plumbing (manifest + SW), even before features. A label without the infrastructure is a lie.

## Other observations

- `--legacy-peer-deps` is still needed for every `npm install` due to `@tailwindcss/vite` not declaring Vite 8 support. This was noted in the #1 retro and is still unresolved.
- `@vue/test-utils` is in devDependencies but unused. Should either use it or remove it.
